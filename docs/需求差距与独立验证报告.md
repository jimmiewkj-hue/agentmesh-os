# AgentMesh OS 需求差距分析与独立验证报告

- 需求基线：`01-需求整理-v1.docx`（项目 README 亦声明以此为唯一基线）
- 被测代码：`agentloop_hub/`（74 个 Python/JS/HTML 文件，21,871 行，其中 Python 13,484 行）
- 验证日期：2026-11-04
- 环境：Windows 11 x64 / Python 3.13.14 / Git 2.47.1
- 独立验证套件：`verification/`（32 个用例，全部通过，31s）

---

## 0. 结论摘要

**七个模块全部有真实代码，不是空框架；主链路（规划 → 审批 → 调度 → 路由 → 隔离执行 → 验证 → 验收 → 合并 → 发布）可运行，四道人类门禁、只追加总线、哈希链表、Worktree 隔离、五级记忆都是真的。**

但距离"实现所有需求"还有三类差距：

| 类别 | 结论 | 严重度 |
| --- | --- | --- |
| **愿景级差距** | 需求的核心承诺是"用户永远只面对一个入口、其它 Agent 全部降级为可调用资源、用户不感知"。实测 14 个 Agent 中**只有 3 个能无人执行**（opencode CLI、Qoder CN、WorkBuddy），7 个必须人工接力（Trae/Trae CN/Qoder 国际版/ZCode/DSH/Cursor/REA），4 个离线。 | **P0** |
| **模块级差距** | 能力路由退化为静态偏好（6/6 种任务类型都选 opencode）；成本优化只有 Token 账、没有美元账（"100 美元→10 美元"无法度量）；独立验证 Agent 直接跑在用户主工作区，不受 Worktree 隔离。 | P1 |
| **真实性差距** | 文档声明的测试数（128/146）与实测（180）不一致；模型数（93）与实测（107）不一致；`/api/overview` 的"七模块 ready"是硬编码字面量；离线 CLI Agent 仍被标记 `auto_executable`。 | P2 |

需求满足度（16 条需求条文，S1-S5 各计 1 条）：**完全满足 12 条 / 部分满足 4 条 / 未满足 0 条**（详见 §2）。

## 1. 需求基线拆解

`01-需求整理-v1.docx` 的可验证需求共 16 条，分三层：

**定位层（3 条）**
- L1 主节点不是 Agent，而是 Controller（Scheduler / Memory / Task Router / Context Manager / Agent Connector）
- L2 用户只面对一个入口，其它 Agent 降级为可调用资源
- L3 三级架构：用户 → Controller → Context Bus → 异构 Agent

**模块层（7 条）**
M1 Agent Connector、M2 Unified Memory、M3 Context Bus、M4 Task Scheduler、
M5 Capability Router、M6 Cost Optimizer、M7 Human Governance

**同步与经济学（6 条）**
S1 Level1 消息、S2 Level2 任务、S3 Level3 上下文、S4 Level4 知识、S5 Level5 工作流、
S6 结果同步而非任务同步（省 Token 的正确方向）

## 3. 关键缺口（按严重度排序）

### P0-1 十四个 Agent 里只有三个能被自动调用

**证据（真机审计 `verification/audit-real-machine.json`）**

| Agent | 状态 | 适配方式 | 可自动执行 | 能力数 | 模型数 |
| --- | --- | --- | --- | --- | --- |
| opencode | online | CLI | ✅ | 18 | 41 |
| qoder_cn | online | GUI 自动化 | ✅ | 17 | 4 |
| workbuddy | online | GUI 自动化 | ✅ | 17 | 11 |
| trae / trae_cn | online | file_relay | ❌ | 12 | 0 |
| qoder（国际版） | online | file_relay | ❌ | 12 | 1 |
| zcode | online | file_relay | ❌ | 12 | 10 |
| dsh | online | file_relay | ❌ | 12 | 40 |
| cursor | online | file_relay | ❌ | 10 | 0 |
| rea | online | MCP | ❌ | 7 | 0 |
| aider / claude_code / codex_cli / gemini_cli | **offline** | CLI | ⚠️ 标记为可自动 | 1 | 0 |

需求原文的示例链路是：`Trae 扫描代码 → Qoder 检查 Bug → OpenCode 生成测试 → Claude 审核架构 → DeepSeek 整理文档 → 返回最终结果，用户不感知`。
实测：Trae、Qoder（国际版）、DSH 全部是 `file_relay`，控制平面只能生成任务包，**必须由用户打开对应软件、粘贴、再回填结果**。这条示例链路无法自动跑通。

> 项目自身文档 `docs/11类Agent能力矩阵.md` 对此是诚实的（"人工接力""GUI 自动化未落地"），但 README 与实现报告把它包装成了"七模块全部落地"，两者存在张力。

### P1-1 能力路由退化为静态偏好：6 种任务类型全部选 opencode

**证据**：`verification/audit-real-machine.json` → `routing_selected`

```json
{"analysis":"opencode","review":"opencode","implementation":"opencode",
 "documentation":"opencode","verification":"opencode","architecture":"opencode"}
```

**成因**：`control/router.py:183` 把能力项写死为 `capability = 1.0`（注释："eligibility already enforced"），于是"能力"占权重 0.40 却对所有人相同；其余 success/verification/speed/cost 在无历史时会全部落在同一个先验值上，最终由 `access_level`（0.02 权重）+ agent_id 字典序决定，opencode（L3、最短 id）恒胜。

**影响**：需求 M5 的"实时评估 Agent 能力 / 成本 / 速度 / 成功率"实际只实现了后三项，且"能力"没有任务类型维度的画像（谁更擅长 review、谁更擅长 architecture），与"代码生成→Claude Code、联网搜索→Gemini、结构化分析→DeepSeek"的诉求不符。

### P1-2 成本优化没有美元维度

**证据**
- `config.py:131` 注释即写明"USD per 1M tokens; populated by the user. Unknown models cost 0."，默认 `pricing = {}`。
- `cost.py:183-192` 的 `record_saving(..., cost_saved=0.0)`，全仓库 **没有任何调用方传过 `cost_saved`**（grep 仅命中函数定义本身）。

**实测**：跑完整个闭环后 `savings_ledger` 只有 `tokens_saved`，`cost_saved` 恒为 `0`（`test_GAP_cost_in_usd_cannot_be_measured_out_of_the_box`）。

**影响**：需求 M6 的商业目标是"把 100 美元变成 10 美元"，当前系统**无法回答"这次省了多少钱"**，只能回答"省了多少 token"。Benchmark 的 `avg_cost` 同样是 0，`cheapest_sufficient` 退化为按 token 排序。

### P1-3 独立验证 Agent 跑在用户主工作区（无隔离）

**证据**：`runner.py:735,740` 把验证请求的 `workdir` 直接设为 `self.project.root`；`_select_verifier()` 在 `require_independent_verifier=True`（默认）时会自动挑一个非执行者的 CLI Agent 作为验证者。

**实测**：`test_GAP_independent_verifier_executes_in_the_live_workspace` —— Mock 验证器写入的 `VERIFIER_CANARY.txt` 落在了**项目根目录**，而不是任何 Worktree。

**影响**
1. 与 README"子任务在独立 Worktree 中执行""Agent 进程不是强沙箱"的边界描述不一致：验证节点连 Worktree 都没有。
2. 一个 LLM 验证者拥有对用户工作区的直接写权限；若它做了"顺手修复"，会污染用户未提交的改动。
3. 每个任务都会额外触发一次验证 Agent 调用（时间与费用翻倍），而 README 未说明该默认行为。

### P1-4 路由失败时丢弃全部淘汰原因

**证据**：`router.py:163-174`，`_choose()` 在 `eligible` 为空时直接 `return None`，`rejected` 列表随之丢弃；`rank_spec()` 因此只能返回 `selected=None, candidates=[]`。

**实测**：`test_GAP_router_drops_all_rejection_reasons_when_nobody_qualifies`。

**影响**：用户看到"没有可用 Agent"时拿不到"谁因为缺哪个能力/离线/需人工被淘汰"，与"可解释的路由"目标相悖。

### P2-1 `/api/overview` 的"七模块 ready"是硬编码

`hub.py:792-796`：

```python
"modules": {
    "connector": "ready", "unified_memory": "ready", "context_bus": "ready",
    "task_scheduler": "ready", "capability_router": "ready",
    "cost_optimizer": "ready", "human_governance": "ready",
},
```

**实测**：把全部 Agent 删除后，`overview()["modules"]` 仍是七个 `ready`（`test_GAP_overview_module_status_is_a_hardcoded_literal`）。
**影响**：`docs/验证日志.md` 里"七个模块状态均为 ready"这条"验证结论"因此没有信息量，属自证式指标。

### P2-2 离线 CLI Agent 仍被标记 `auto_executable`

`connectors.py:143-151`：`if kind in ("cli", "opencode"): return True`，不检查状态。
真机结果：aider / claude_code / codex_cli / gemini_cli 均为 `offline`，但 manifest 里 `auto_executable=True`、`capability=["auto_executable"]`。
路由器因"状态 offline"仍会拒绝它们，**功能无害，但对外能力声明失真**，与"未安装不虚构能力"的原则冲突。

### P2-3 文档与实测数字漂移

| 指标 | 文档声明 | 实测 |
| --- | --- | --- |
| 自动化测试数 | `README.md` 146 / `docs/实现与测试报告.md` 128 / `验证日志.md` 128 | **180**（180 collected，全绿，3m08s） |
| 本机模型数 | 93 | **107** |
| 代码规模 | 17,344 行 / 64 文件 | 21,871 行 / 74 文件（含 html+js） |

### P2-4 需求文末列出的"下一步文档"缺 5 份

需求原文列了 10 份可交付文档。现有 `docs/` 覆盖：概要设计、用户手册、实现与测试报告、验证日志、能力矩阵、GUI 实测、Qoder 工作区确认。
**缺**：Agent 通信协议规范、Memory 设计（独立成篇）、Context Bus 设计（独立成篇）、MCP 兼容方案、VSCode/Trae 插件方案、0→1 路线图、与 AutoGen/CrewAI/OpenHands/LangGraph 的差异化分析。

### 其它已确认但影响较小的限制

- **G-6 记忆是 push 而非 pull**：需求说"任何 Agent 启动时直接读取 Memory"，实现是控制平面把 bootstrap 塞进 prompt。外部 Agent 无法通过 MCP 主动拉取（项目没有 MCP Server，只有 MCP Client；HTTP 侧有 `/api/memory/bootstrap` 但无鉴权、未文档化为 Agent 接口）。
- **G-7 任务拆分无兜底**：`planning.py` 完全依赖主 Agent 产出 `plan.json`，失败只重试一次修复；主节点不可用时没有确定性降级路径。
- **G-8 语义缓存不是语义**：`cost.py:47` 是词袋 Jaccard 相似度（阈值 0.82），仅对只读任务 + 相同文件基线生效。文档已如实说明，不算虚标，但达不到"语义缓存"字面预期。
- **G-9 无跨进程互斥**：只有进程内 `threading.Lock`，同一项目开两个 `agentmesh serve` 时依赖 SQLite WAL + `busy_timeout` 兜底，Worktree 创建路径存在竞争窗口。
- **G-10 GUI 自动化依赖窗口相对坐标**（`discovery.py` 中的 `input_offset_ratio` 等），应用改版即失效，需人工校准。

## 4. 独立验证怎么做、验证到了什么

### 4.1 方法

1. **不复用项目夹具**：`verification/` 自建 Git 仓库、自建 Hub、自注册 mock CLI Agent（真实子进程，走真实 `AGENTLOOP_*` 文件契约）。
2. **需求条文 → 用例**：32 个用例逐条对应 §1 的 16 条需求，其中 6 个是 `test_GAP_*` 缺口探针（**通过即证明缺口存在**）。
3. **真机审计**：`verification/audit_real_machine.py` 用真实发现路径扫描本机，产出 `audit-real-machine.json`（14 Agent / 107 模型 / 路由结果 / 五能力矩阵）。
4. **交叉核对**：把项目已有日志（`logs/zero-input-e2e-20261104/`）作为第三方证据，与代码结论互证。

### 4.2 结果

```text
python -m pytest -o addopts="" -q        → 180 个基线用例全部通过（3m08s）
python -m pytest verification -q         → 32 个需求用例全部通过（31s）
python verification/audit_real_machine.py → 14 Agent / 107 模型 / 3 个在线可自动执行
```

**通过的正向证据（节选）**

- 四道门禁真的拦得住：未过验收调用 `merge()` 抛 `ValidationError`；过验收但无合并审批抛 `ApprovalRequiredError`；未合并申请发布抛 `ValidationError`；架构任务未批架构就批计划抛 `ApprovalRequiredError`。
- 总线真的只追加：直接 `UPDATE bus_events` 被 SQLite 触发器拒绝（`IntegrityError`），哈希链 `verify().ok=True`。
- 调度真的按 DAG：`T002.started_at >= T001.finished_at`；一次失败后重试成功（`attempts=2`）；3 个终态失败触发熔断（run → `paused`）。
- 缓存真的命中：同一只读分析计划跑第二遍，`savings` 出现 `exact_cache`。
- 独立验证门禁真的能抓假：`logs/zero-input-e2e-20261104/final-run-status.json` 记录了真实 GUI 闭环的一次失败 —— Agent 声称测试通过，控制平面复跑 `pytest` 失败，任务被判 failed。
- 真实跨 Agent 闭环确实跑通过（两次，非模拟）：Qoder CN 主 + WorkBuddy 子（`run_2a3190ab7841`，204.5s，`pending_acceptance`→merge→`released`）、WorkBuddy 主 + Qoder CN 子（`run_13092b919fb0`，270.9s，`released`），均为零 OS 输入（CDP/deeplink/DB 配置）。

**缺口探针（6 个全部"通过"，即缺口成立）**

| 探针 | 证实的缺口 |
| --- | --- |
| `test_GAP_most_products_still_need_a_human_in_the_loop` | 14 个产品中 9 个无法无人执行 |
| `test_GAP_offline_cli_agent_is_still_marked_auto_executable` | 离线 CLI 仍带 `auto_executable` 能力 |
| `test_GAP_router_drops_all_rejection_reasons_when_nobody_qualifies` | 无候选时路由不可解释 |
| `test_GAP_cost_in_usd_cannot_be_measured_out_of_the_box` | 美元节省恒为 0 |
| `test_GAP_independent_verifier_executes_in_the_live_workspace` | 验证节点不受 Worktree 隔离 |
| `test_GAP_overview_module_status_is_a_hardcoded_literal` | 七模块 ready 是常量 |

## 7. 一句话总结
