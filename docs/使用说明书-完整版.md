# AgentMesh OS 使用说明书（完整版）

- 适用版本：2026-11-05 构建（含链路绑定计划、统一执行入口、节点阻塞恢复、启动器重启保护、真实上下文/能力选项与触发同步）
- 适用对象：在本机同时使用 Trae / Qoder / WorkBuddy / OpenCode 等 Agent 的开发者
- 核心承诺：**一个 WebUI 入口、一个工作目录、一份 Prompt，多个 Agent 协作完成；全程零 OS 键鼠；不调用厂商私有 HTTP API。**

---

## 0. 五分钟快速开始

```bash
cd D:/qoder/agent-hub
python -m pip install -r requirements.txt

# 关键环境变量（必须）
export AGENTMESH_DISABLE_GUI_INPUT=1        # 硬锁 OS 键鼠/剪贴板
# AGENTMESH_ALLOW_APP_RESTART=1 可选：允许任务执行时自动重启无 CDP 的桌面应用。
# 默认不设置。应用运行但未开放调试接口时，WebUI 会阻塞该节点并弹窗，
# 由用户点击「重启 Agent 接口」触发一次优雅重启（会先备份状态库）。
export AGENTMESH_TRAE_CDP_PORT=9342
export AGENTMESH_QODER_CDP_PORT=9222
export NO_PROXY=127.0.0.1,localhost
unset ELECTRON_RUN_AS_NODE NODE_OPTIONS     # 从 WorkBuddy 继承会导致 Electron 秒退

python -m agentloop_hub serve --port 8801
# 浏览器打开 http://127.0.0.1:8801
```

然后在 WebUI 里按 ①项目目录 → ②Prompt → ③主/子 Agent 与模型 → ③.5 链路 → ④审批与运行 的顺序操作。
只想先验证环境：先点 **③.5 的“预检并打开 Agent”**，看到全部 ✅ 再运行。

## 1. 核心概念

| 概念 | 含义 | 在 WebUI 的位置 |
| --- | --- | --- |
| 工作目录 | 你选定的 Git 项目根目录；所有任务的隔离 Worktree 都从它派生 | 第 1 步 |
| 主 Agent | 负责理解需求、拆分任务、汇总结果；**不直接改代码** | 第 3 步左栏 |
| 子 Agent | 真正执行任务的 Agent（Trae / Qoder / OpenCode / WorkBuddy…） | 第 3 步右栏、第 3.5 步链路 |
| 阶段（Stage） | 链路中的一个任务，绑定一个 Agent + 一个真实模型 | 第 3.5 步 |
| 零输入 | 不合成任何 OS 鼠标/键盘/剪贴板事件；只走应用自身接口 | 全局 |
| 绑定（Binding） | 某次运行中，每个任务实际使用的 Agent / 模型 / 工作区 | 第 4 步与 `/api/runs/<id>/bindings` |

**工作目录与任务目录的关系**

```text
<工作目录>                                   ← 你设定，GUI Agent 打开的就是它
└── .agentloop/
    ├── runs/<run_id>/worktrees/<task_id>/   ← 每个任务真正执行的地方（隔离）
    ├── tasks/<run_id>_<task_id>/            ← 任务包、prompt、result、日志
    └── state.db                             ← 审计、总线、租约、审批
```

## 2. 安装与启动

### 2.1 依赖

- Python 3.11+（本机 3.13）
- Git（工作区必须是 Git 仓库）
- `requirements.txt`：`PyYAML`、`cryptography`、`zstandard`、`pytest`、`websocket-client`

### 2.2 启动 WebUI

```bash
python -m agentloop_hub serve --host 127.0.0.1 --port 8801
```

- 打开 `http://127.0.0.1:8801`
- 端口被占用时换一个端口；**不要**用 8790（本机已被其他程序占用）

### 2.3 首次探测

- 第 3 步右下角“重新探测 Agent”：重新扫描本机安装
- “刷新全部模型”：立即重新读取每个 Agent 的真实模型目录
- “同步模型（全部）”：全量同步并写入 `models-sync.json`；之后**每天自动同步一次**
  （控制台每小时检查，超过 24 小时即刷新）
- 下拉里的模型名显示为**应用内同款名称**（如 `DeepSeek-V4.1-Flash`、`GLM-5.3-Flash`），
  并附带真实倍率（如 `x0.12`）；底层仍用该 Agent 的模型 id 执行
- 也可以命令行：`python -m agentloop_hub discover`

## 3. 配置：工作目录、主 Agent、子 Agent、模型

### 3.1 第 1 步：设定工作目录

1. 输入绝对路径，例如 `D:\projects\my-app`
2. 新项目点“初始化项目”（自动 `git init` + 首次提交）；已有项目点“打开已有项目”
3. 可选：设置项目 token 预算。**默认 0（不限）**；预算只用于统计与 80% 告警，
   **不会因为超预算自动停止任务**。任务的开始/暂停/继续完全由你操作。

> 工作目录必须是 Git 仓库；非 Git 目录会被拒绝（这是合并/回滚的前提）。

### 3.2 第 3 步：主 Agent 与模型

- 主 Agent 负责：理解 Prompt → 生成计划 → 汇总结果
- 建议选**快且稳**的模型（如 OpenCode 的 `opencode/glm-5.3-flash-free`、Qoder 的 `dfmodel`），
  因为主节点只做规划/汇总，不需要最强模型
- “模型”下拉里的每一项都来自该 Agent 的真实目录，不存在虚构项
- 主 Agent 也可设置**上下文长度**（tokens，0=默认）和**能力等级**；
  选项来自所选模型的真实配置（见 3.3.3），保存后写入该 Agent 的模型 profile，
  规划和汇总时生效；不在选项内的值会被后端拒绝

### 3.3 第 3 步：子 Agent 与模型

- 每个子 Agent 一行，可单独选模型；选择后点击“保存”
- 同一行还可设置**上下文长度**（tokens，0=默认）和**能力等级**；
  配置按“Agent + 模型”保存，切换模型后会带出该模型上次保存的值
- 输入框/下拉的选项由该模型的真实配置动态生成（见 3.3.3）；
  能力等级用于智能选型的质量加权；上下文长度会写入任务包，并在较小时压缩中间上下文
- 只有被选中的 Agent 才会在运行时被打开
- 状态为 `offline` 的 Agent 不会被路由

### 3.3.1 完全控制（默认勾选）

第 3 步新增「完全控制」复选框，默认勾选。它解决的问题是：GUI Agent 在工作区外读取/执行/写入时，
可能弹出需要用户确认的权限框，导致对话一直等待。

- 勾选：任务开始前切到 Agent 自己的完全访问模式；运行期间由 CDP DOM watcher 自动接受残留确认。
- 取消：保持 Agent 默认权限，确认留在应用内由你手动处理。
- 仅本机、仅 GUI 接口；不合成 OS 键鼠/剪贴板。
- 风险：完全访问意味着 Agent 拥有与用户本人相当的本机权限；生产任务建议按需关闭。

各 Agent 的实测接口见 [完全控制与权限自动接受](完全控制与权限自动接受.md)。

### 3.3.2 多轮自动续跑（默认勾选）

同一位置新增「多轮自动续跑」复选框和最大轮次输入，默认勾选、最多 3 轮（含首轮）。

- 一轮结束后，主节点汇总若为 `reject` 或仍有失败任务/验证失败，控制平面不会直接结束，而是：
  1. 让主节点基于上一轮未解决项重新规划最小增量任务；
  2. 主节点规划失败时，用失败证据生成回退修复任务 + 主节点复审任务；
  3. 在同一运行、同一工作区历史里继续执行，保留记忆、Context Bus、补丁与审计。
- 结束条件：主节点批准且任务/验证通过；同一阻塞连续出现；达到最大轮次；或下一轮计划无法生成。
- 阻塞时运行进入 `waiting_user`，不创建验收审批；点击「继续运行」会追加一轮额度并清除阻塞。
- 关闭后恢复旧行为：一轮结束即进入验收/合并门禁。
- 详细判定与实测见 [多轮对话与完成判定](多轮对话与完成判定.md)。

### 3.3.3 上下文长度与能力等级：来自各应用真实配置

AgentMesh 不内置通用能力档位。主/子 Agent、链路节点“编辑绑定”里的选项，
全部来自对应应用自己的模型目录；切换模型后选项立即变化：

| 应用 | 上下文长度 | 能力/思考等级 | 证据来源 |
| --- | --- | --- | --- |
| WorkBuddy | `300000 / 600000 / 1000000` | `low / high / max`（低/高/极高），默认 `high` | `~/.workbuddy/local_storage/*.info` 的 `contextWindow.supportedLengths`、`reasoning.supportedEfforts` |
| Trae / Trae CN | `1000000` | `light / high / extra_high`（轻/高/极高），默认 `high` | `state.vscdb` 的 `AI.agent.model.model_list_map` |
| Qoder CN | 当前值（本机实测 `1000000`）；本地库不公布固定档位，因此不伪造上限 | `none / minimal / low / medium / high / xhigh / max`（关闭思考/最小/低/中/高/极高/最大） | `main.sqlite` 的 `chat_model_preferences` 与应用内置选项 |
| 其他 CLI/文件接力 | 任意非负整数（0=默认） | `low / medium / high / ultra` 兼容值 | 无应用级选项，按通用值校验 |

**触发时同步写入**（不是只写 AgentMesh 自己的数据库）：

- WorkBuddy：先通过 CDP 写应用自己的新任务偏好
  （`model-context-window`、`cb-effort:by-model:<uid>`、
  `cb-thinking-pref:by-model:<uid>`、`cb-newtask:model:<uid>`）；
  值有变化时调用应用自身页面 `location.reload()` 让偏好生效，等待输入框就绪后再发 deeplink。
  会话入库后再写 `sessions.context_window/thought_level` 并回读。
  该流程已在真机验证：600000/low 与 1000000/high 均出现在新会话行中。
- Trae：把思考等级写入 `<uid>:AI.agent.model.reasoning_effort_level_by_agent_model_v2`；
  Trae 当前上下文固定为 1M，没有单独的长度下拉；
- Qoder：把上下文/思考强度写入 `chat_model_preferences.context_window`、
  `reasoning_effort`，写后回读。

任一写入失败会抛出 `PROFILE_SYNC_FAILED`，该节点失败并阻塞链路，
不会带着错误配置继续执行。保存或编辑绑定时提交了不在真实选项内的值，后端直接拒绝并返回可选值。

> WorkBuddy 改变偏好时的一次页面 reload 只重载渲染器，不重启进程、不丢失登录；
> 若偏好与上次相同则不会 reload。

> 旧版本允许 WorkBuddy 填写 `200000` 等任意数字；升级后该值会显示在输入框中但不在选项内，
> 子 Agent 行会显示“配置警告：上下文 200000 不在真实选项 …”。
> 请在下拉/输入提示中改选 `300000`、`600000` 或 `1000000`，否则执行前会被校验拒绝。

### 3.4 第 3.5 步：链路配置（只保存，不执行）

链路 = N 个阶段串行 DAG，每个阶段固定一个 Agent + 一个真实模型。
**阶段数量跟随第 2 步生成的计划任务数量**；没有计划时可以增删阶段创建独立链路。

1. 先生成任务计划；3.5 会自动载入该计划的 N 个阶段（也可点“从计划载入阶段”手动载入）
2. 每个阶段选择：Agent / 模型 / 任务类型
3. 选型策略：
   - **最省优先**：在质量前 80% 的候选里选成本最低
   - **均衡**（默认）：质量前 90% 里选成本最低，并给出“价值最高”备选
   - **效果优先**：直接选综合价值最高的组合
4. 点“智能选型”：自动填好每个阶段的 Agent + 模型
5. 点“预检并打开 Agent”（可选）：显式打开应用、绑定工作区与模型并回读核验；
   会提示将重启 Trae/WorkBuddy。CDP 已存活时优先复用，不杀进程
6. 点“保存链路配置（待审批）”：只把每阶段的 Agent/模型/类型写入当前计划，
   **不会批准计划、不会创建运行、不会启动任何 Agent**

> 配置会同时保存到 `<项目>/.agentloop/chain-draft.json` 和浏览器 localStorage；
> 页面刷新、服务重启都不会回到默认三个阶段。脚本版本变化时浏览器自动加载新 `app.js`。

**唯一执行入口在第 4 步**：

```text
3.5 保存配置 → 4 批准计划 → 4 开始执行
```

**暂停 vs 停止**：

- “暂停运行”：当前 Agent 回合会跑完，后续不再派发；适合等一个节点自然结束。
- “停止运行（取消节点）”：立即取消排队/运行/阻塞节点，置运行 canceled，
  中断 GUI reader 等待，并尝试点击 WorkBuddy 自己的停止按钮；取消后不能 resume，只能新建运行。

**同 Agent 会话续接**：

- 主 Agent 的规划/汇总会话独立；
- 链路第一个节点为该 Agent 新开会话；
- 后续节点若仍是同一 Agent 且模型相同，直接续接该 Agent 上一节点会话，
  并在同一工作树中继续，不再重新读取上一节点成果；
- 遇到不同 Agent 才新开会话；之后再回到先前的 Agent 时继续其原会话；
- 模型变化时保留该 Agent 工作树，但新开会话（避免跨模型上下文污染）；
- 同一 Agent 节点必须串行；不同 Agent 仍可按依赖并行。

**运行中编辑节点绑定**：

第 4 步链路节点表每个未完成节点都有“编辑绑定”：
- 可修改 Agent、模型、上下文长度、能力等级；
- 排队/阻塞/等待节点保存后立即生效；
- 正在运行/验证中的节点需等结束或重试后再改；
- 修改只影响该任务，不改 Agent 全局默认配置。

**节点阻塞与恢复**：

- 某个节点的 Agent 未成功运行（应用无调试接口、发送按钮禁用、需要手动审批）时，
  任务与运行进入 `waiting_user`，WebUI 右上角弹窗提醒；
- 弹窗会写明 Agent、节点、原因与任务说明文件；
- 高风险任务会先停在“高风险操作审批”；WebUI 顶部弹窗会显示操作内容、风险与文件范围，点“批准高风险并继续”即可；不要在未批准时反复点“继续运行”。
- 应用无接口 → 点“重启 Agent 接口”（优雅关闭后重启一次）；
- 已预填但发送按钮禁用 → 切换到 Agent 应用手动点击“发送/审批”；
- 节点完成后，弹窗自动消失，链路自动继续下一节点；阻塞期间不会提前启动下游节点。

**稳定性细节（2026-11-05 第二轮）**

- WorkBuddy 写 `result.json` 后仍可能在收尾；控制平面会等会话真正完成，
  不会立刻启动下一个 WorkBuddy 任务。
- WorkBuddy 还有运行中的任务时，新节点会等待；超时弹窗 `agent_busy`，
  请等待或先停止旧任务，避免两个对话互相覆盖。
- 计划里的中文 scope 会提取为路径/glob；`.agentloop/planning/.../workspace` 绝对路径
  会改写为任务工作区，PowerShell 验证命令会自动用 PowerShell 执行。
- Trae 未登录时会弹窗 `login_required`，请先在 Trae CN 内登录再重试；
  不再误报“模型不存在”。
- 第 4 步“主节点活动”卡片显示主节点当前的规划轮次/汇总、Agent、模型、耗时和错误，
  这样 Trae 打开时能明确知道它在执行哪个阶段。
- 链路节点表的“耗时/上限”列显示每个节点已运行时间和计划里的 `time_limit_minutes`。
- WorkBuddy 模型长时间“深度思考中”但 transcript 没有新事件时，不再按 600s 直接判失败；
  会先检查会话 DB 的 working 状态和 UI 的思考/停止按钮。
- WorkBuddy 上游流错误（如 `Empty stream: finish_reason=error`）会原样显示为
  `MODEL_STREAM_ERROR`，不会再误报“600s 无事件”。
- 同一节点自己的上一 WorkBuddy 会话仍在运行时，弹窗会明确说明，不会误说成“另一个任务”，
  也不会新开第二个会话。
- 计划偶尔漏写入口文件（例如 `src/main.js`）。默认 `scope_violation_policy=warn`：
  普通项目内越界显示“验证警告”但任务继续；明确 out_of_scope、越出项目或高风险文件仍失败。
  需要严格门禁时在 `.agentloop/config.json` 设 `"scope_violation_policy": "strict"`。
- 浏览器验证命令（Chrome/Edge headless）会自动启动项目 `tools/serve.py`、使用独立临时
  profile，并把 `--screenshot` 相对路径转成任务工作区绝对路径，避免“找不到路径”和端口未启动。

**每阶段任务类型**

| 类型 | 用途 | 是否写文件 | 默认范围 |
| --- | --- | --- | --- |
| `analysis` | 扫描、理解 | 否 | — |
| `review` | 查 Bug、复核 | 否 | — |
| `implementation` | 改代码、生成测试 | 是 | `tests/**`、`test_*.py` |
| `verification` | 只读验证 | 否 | — |
| `documentation` | 写文档 | 是 | `tests/**`、`test_*.py` |
| `architecture` | 架构设计（需额外审批） | 否 | — |

> 可写阶段如要改 `src/`，必须在阶段参数里显式传 `scope`；默认只允许测试目录。

### 3.5 第 2 步：输入 Prompt

- 主 Agent 用这个 Prompt 生成计划；链路模式下它作为总目标
- 建议写清：目标、边界（不要改什么）、验收标准
- 点“生成任务计划”走“主 Agent 规划”路径；随后在 3.5 保存该计划的阶段绑定，再到第 4 步批准并开始执行。固定链路（无预设计划）同样走“3.5 保存 → 4 批准 → 4 开始”。

## 4. 运行：审批、执行、验收、合并、发布

### 4.1 四道人类门禁

| 门禁 | 何时出现 | 你必须做什么 |
| --- | --- | --- |
| 架构审批 | 计划含 `architecture` 任务 | 先批架构，再批计划 |
| 计划审批 | 每次导入计划 | 确认任务拆分与范围 |
| 验收 | 所有任务完成 | 看结果与验证报告，决定接受/退回 |
| 合并 | 验收通过 | 批准合并，补丁才写入工作目录 |
| 发布 | 合并完成 | 批准发布（可回滚） |

### 4.2 执行过程

- 每个任务在 `.agentloop/runs/<run_id>/worktrees/<task_id>` 独立执行
- GUI Agent 会被切到该 Worktree；CLI Agent 的 cwd 就是该 Worktree
- 完成后生成 `patch`，验收通过才合并到主工作目录
- 任何一步失败都会写 `error` 与证据，不会“假装成功”

### 4.3 查看绑定（每个任务实际用了什么）

- WebUI：运行结束后第 3.5 步下方自动出现“每阶段实际绑定”表
- API：`GET /api/runs/<run_id>/bindings`
- 字段：`agent_id / model / workspace / status / verification / visible_model / verified / error`

## 5. 所有 Agent 如何被设置工作区与模型

### 5.1 逐款机制

| Agent | 工作区怎么设 | 模型怎么设 | 核验 |
| --- | --- | --- | --- |
| Trae / Trae CN | 写 `state.vscdb` 的 `solo-lite.local-project-folders` / `project-workspace-cache` / `mode-state-map.session.workspacePath`；启动带 `--folder-uri` | **CDP 页面级鼠标事件**打开应用自己的模型菜单并点选（`Input.dispatchMouseEvent`，不碰 OS 光标），再写 store 持久化 | 回读 `.model-select-area-model` 文本 |
| Qoder CN | `main.sqlite` 的 `workspaces` + `chat_sessions.cwd/workspace_id`；迁移 transcript 的 `workspace-directories`；重启应用 | `chat_sessions.model` + transcript `runtime-config.model` | 回读 `assistant.model` + daemon `open_session cwd` |
| WorkBuddy | `workbuddy://task?action=start&cwd=<path>` | `...&model=<id>` | `workbuddy.db sessions.cwd/model/source_mode` |
| OpenCode | 进程 cwd / `--dir` | `-m <model>` | stdout JSON 事件 |
| ZCode / DSH / Cursor | 仅只读识别，当前不参与自动执行 | 未实现零输入切换 | — |

### 5.2 “预检并打开 Agent”做了什么

`POST /api/preflight`（WebUI 按钮）对每个选中阶段：

1. 校验模型是否在该 Agent 的真实目录里
2. GUI Agent：CDP 已存活则复用原进程，只通过应用自己的 CLI 打开目标文件夹；
   应用未运行则启动带调试端口的实例；应用运行但无 CDP 时才优雅重启（先备份状态库）
3. CLI Agent：校验可执行文件
4. 返回表：`process / workspace_set / model_set / visible_model / ok / error`

> 预检可能关闭并重新打开 Trae/WorkBuddy（仅在必须开启调试接口时），请先保存手头工作。
> 任务执行路径默认**不会**自动重启正在运行的应用；它会阻塞并让 WebUI 询问你。

**本机实测（2026-11-04）**

```text
ready 3 / 3
trae_cn   ok=True process=running ws=True model=True visible=DeepSeek-V4.1-Flash
qoder_cn  ok=True process=running ws=True model=True
opencode  ok=True process=cli     ws=True model=True
```

预检的 Qoder 校验会跳过 daemon 的“上一次会话 cwd”（应用刚重启、尚未开新回合），
以 transcript 的 `workspace-directories` 与 `assistant.model` 为准；任务执行时的校验仍然严格比对 daemon。

### 5.2.1 模型目录如何保持同步

| 来源 | 读取方式 | 覆盖 |
| --- | --- | --- |
| Trae / Trae CN | `state.vscdb` 的 `solo_agent` 目录（与输入框菜单同源） | 19 个（含 DeepSeek-V4.1-Flash / GLM-5.3-Flash） |
| Qoder CN / 国际版 | `main.sqlite` 的 `chat_model_preferences` + 会话模型 | 10 / 14 个键 |
| WorkBuddy | 产品清单 `local_storage/*.info`，过滤内部补全模型，读取 `credits` 倍率 | 30+ 个 |
| OpenCode | `opencode models` CLI | 41 个 |
| ZCode / DSH | 本地 rollout / settings | 10 / 40 个 |

同步结果写入 `<工作目录>/.agentloop/models-sync.json`，WebUI 第 3 步会显示“上次同步时间”。
也可以命令行执行：`python -m agentloop_hub models sync`；若要脱离控制台每天跑，可用 Windows 计划任务调用该命令。

### 5.3 为什么任务执行时工作区是 Worktree 而不是工作目录

- 隔离：多个 Agent 并行改代码不会互相覆盖
- 可审计：每个任务的 patch 独立生成
- 可回滚：合并前随时丢弃

你在 WebUI 设定的工作目录是“项目根”，所有 Worktree 都是它的子目录（`.agentloop/runs/...`）。

## 7. 费用最低、效果最好

### 7.1 选型算法（可解释）

`GET /api/models/recommend?task_type=<type>&profile=<cost_first|balanced|quality_first>`

```
候选 = 满足该任务能力要求 且 在线 的 (Agent, 模型)
质量 = 该 Agent 的历史 benchmark 分数（无历史用 0.5 先验）
成本 = 模型级：
        - 模型名含 free            → 0
        - Trae 模型                → 应用目录里的真实倍率（如 GLM-5.3-Flash 0.08x）
        - 其他                     → 0.5（估计值，界面会标注 estimated）
价值 = 0.55*质量 + 0.25*验收通过率 + 0.20*速度
推荐 = 质量 ≥ 阈值 的候选里，成本最低者（阈值随策略 80%/90%/100%）
```

界面会显示每个阶段的推荐理由与 `cost_source`，**不把估计值伪装成真实价格**。

### 7.1.1 预算与任务启停（重要）

- 新项目默认 **预算 0 = 不限**；已有的 1000000 只是历史默认值，**不会拦截任务**。
- 预算只用于：顶部 80% 告警、成本页统计、选型参考。
- **任务的开始/暂停/继续完全由你操作**：
  - 第 4 步“最近运行”里：运行中显示“暂停运行”，暂停后显示“继续运行”
  - API：`POST /api/runs/<id>/pause`、`POST /api/runs/<id>/resume`
  - 暂停只阻止**后续任务派发**；正在跑的那一个会自然结束（不会强杀进程）
  - 需要硬性预算门禁时，显式在 `.agentloop/config.json` 设 `"budget_hard_stop": true`

### 7.2 省钱手段（按效果排序）

1. **用 free 模型**：OpenCode 的 `opencode/*-free` 成本为 0，适合扫描/复核/测试生成
2. **用 Trae 低倍率模型**：`GLM-5.3-Flash 0.08x`、`Seed-Code 0.06x`、`DeepSeek-V4.1-Flash 0.12x`
3. **结果复用**：只读任务会命中语义/精确缓存，第二次同任务几乎零成本
4. **上下文压缩**：结果包只传摘要，不传全量工具日志
5. **项目/主节点预算**：达到 80% 会在顶部告警
6. **阶段裁剪**：能用 2 段完成就不要 3 段；每段都要读 prompt + 产出 result

### 7.3 效果保障

- 独立验证：控制平面复跑测试/范围检查，Agent 声称完成不算数
- 验收门禁：不通过不能合并
- 版本台账：模型/客户端升级导致漂移会被记录
- 基准评测：`agentmesh benchmark` 按成功率、验收率、成本、速度打分，反哺选型

## 9. 常见问题

### 9.1 预检里 Trae 显示 `NO_MODEL_SELECTOR`

- 原因：Trae 未启动到工作台，或版本改版导致类名变化
- 处理：确认窗口已打开且输入框可见；改版需更新选择器（`trae_interface.open_trae_model_menu`）

### 9.2 Trae 模型切换成功但发送后排队

- 现象：界面出现“排队提醒，你排在 N 位”
- 处理：换低倍率/低队列模型（GLM-5.3-Flash、Seed-Code），或错峰

### 9.3 Qoder 预检失败 `没有可用的 Qoder 会话`

- 原因：Qoder 从未登录/没有历史会话
- 处理：手动打开 Qoder 新建一次对话，再预检

### 9.4 OpenCode 任务长时间无输出

- 原因：非交互执行需要 `--auto`（已默认开启）；免费模型长任务可能排队
- 处理：换 `opencode/glm-5.3-flash-free` 或缩短任务；查看 `logs/opencode.stdout.log`

### 9.5 报“文件范围与其他任务冲突”

- 原因：上一次中断留下 `file_leases`
- 处理：`POST /api/recover` 或 `agentmesh recover`；新版本启动时会自动清理孤儿租约

### 9.6 CDP 端口 502 / 连不上

- 原因：宿主导出了 `HTTP_PROXY`，把 `127.0.0.1` 也代理了
- 处理：项目已内置 `ProxyHandler({})` 绕过；自建脚本请加 `NO_PROXY=127.0.0.1,localhost`

### 9.7 拉起的 Electron 应用秒退

- 原因：继承 `ELECTRON_RUN_AS_NODE=1`
- 处理：项目已自动剔除；自建脚本需 `unset ELECTRON_RUN_AS_NODE NODE_OPTIONS`

### 9.8 合并被拒“工作区存在重叠的未提交修改”

- 原因：主工作目录有未提交改动，且与 patch 文件重叠
- 处理：先提交/暂存，或缩小任务 scope

## 10. 安全与合规

- **零 OS 输入**：`AGENTMESH_DISABLE_GUI_INPUT=1` 时，任何键盘/鼠标/剪贴板合成都会抛 `GUI_INPUT_FORBIDDEN`
- **CDP 页面事件**：`Input.dispatchMouseEvent` 只进渲染进程，不移动系统光标、不调用 `SendInput`
- **不调厂商 HTTP**：不读取 `storage.json` 的 token，不请求 `llm_utils_chat` 等私有端点
- **状态库备份**：每次写 Trae `state.vscdb` 前自动备份
- **最小权限**：GUI Agent 只拿到任务 Worktree；写范围受 `scope` 约束
- **可回滚**：合并前可丢弃；合并后可 `rollback`

## 13. 三条实操路径

### A. 固定链路（无预设计划）

工作目录 → 第 3.5 步添加/删除阶段（1..N）→ 选 Agent/模型/类型 → 保存链路配置（待审批）
→ 第 4 步批准计划 → 开始执行 → 验收 → 合并 → 发布。

### B. 主 Agent 规划（推荐）

工作目录 → 主 Agent + 模型 → 输入 Prompt → “生成任务计划”（N 个任务）
→ 3.5 自动载入 N 个阶段 → 调整 Agent/模型 → 保存链路配置（待审批）
→ 第 4 步批准计划 → 开始执行。
适合需求复杂、需要主 Agent 拆分的场景。

> 任一节点阻塞时，按右上角弹窗处理；节点完成后自动继续，不需要重新点“开始执行”。

### C. 单 Agent 直跑

CLI：`python -m agentloop_hub ask "检查 calc.py 的缺陷" --agent trae_cn --model deepseek-v4.1-flash`
适合快速验证某个 Agent 是否可用。

## 14. 已知限制（如实告知）

1. **Trae 国际版菜单**按同一 profile 支持，但本机只实测了 Trae CN。
2. **OpenCode 免费模型**长任务可能排队超过 10 分钟；接口本身已直连验证。
3. **ZCode / DSH / Cursor** 目前只有只读接口，不参与自动执行。
4. **未安装的 4 款 CLI**（Claude Code / Gemini CLI / Codex CLI / Aider）只登记参数，未实测。
5. **模型质量是 Agent 级**（历史 benchmark），不是模型级；选型会明确标注 `cost_source` 与先验来源。
