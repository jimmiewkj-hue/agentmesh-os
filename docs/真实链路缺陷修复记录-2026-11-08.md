## 2. 逐项实现明细

### 2.1 Trae 信任对话框（缺陷 #1）

**根因**：`open_trae_workspace()` 启动 `--folder-uri` 后只轮询 `state.vscdb` 工作区登记；
信任对话框（`.monaco-dialog-box`）遮罩期间登记不完成 → 20s 超时 `WORKSPACE_MISMATCH`；
模型菜单同时 0 项 → `MODEL_UNAVAILABLE`。全包无任何信任处理代码。

**实现**（`agentloop_hub/control/trae_interface.py`）：

- `TRAE_TRUST_PROBE_JS`：扫描 `.monaco-dialog-box / [role=dialog] / .dialog-box`，按
  「信任 / trust」文本筛选，报告按钮与肯定项（`是，我信任此作者`、`Yes, I trust the authors`、
  `Trust this folder` 等）的坐标；**绝不点击否定项**。
- `TRAE_TRUST_CLICK_JS`：按精确 label 点击肯定按钮，使用与人工实测相同的
  PointerEvent/MouseEvent 序列（记录 7068 行的人工脚本是唯一已验证路径）。
- `dismiss_trae_trust_dialog(port, page_id, timeout_seconds)`：多页面探测、点后复查；
  返回 `dismissed / TRUST_DIALOG_NO_CONFIRM / TRUST_CLICK_INEFFECTIVE / CDP_UNAVAILABLE`。
- 接入点：
  - `open_trae_workspace` 轮询期间持续清除（超时证据记录 `trust_dialog`）；
  - `ensure_trae_cdp` 复用路径与启动路径（新窗口）各清一次；
  - `select_trae_model_via_cdp` 每轮菜单尝试前清除；无法确认 → `WORKSPACE_TRUST_REQUIRED`；
  - `send_trae_prompt` 发送前清除；无法确认 → 抛 `WORKSPACE_TRUST_REQUIRED`。
- `gui/base.py` 注册错误码；GUI 适配器把该错误归入阻塞码，`kind=workspace_trust`，
  WebUI 显示"在应用内点击信任后重试"并提供重试按钮（不自动重发）。

**边界**：单测用脚本化 CDP 替身验证探测/点击/否定项保护/无效点击/轮询/集成；真实 Trae
窗口的自动化点击需在本机桌面应用上复跑（本轮未重启用户的 Trae 实例，避免打断其会话）。

### 2.2 evidence 草稿路径（缺陷 #2）

**根因**：GUI Agent 习惯把 `.agentloop-task/**` 下的日志/截图当证据；该目录按设计被
patch 排除，冻结验证树永远没有它 → `evidence_files: failed`（T003/T004/T005/T006 四次）。

**实现**（`control/verification.py`）：

- 证据路径为 `.agentloop-task/` 草稿（含绝对路径中的该段）时，先到执行工作树
  `task.workdir` 解析，再回退验证树；命中执行树时在报告中记录
  `draft_evidence_from_execution_worktree`（透明、不丢证据）。
- 非草稿证据仍只认验证树（"源码只在执行树、没进补丁"仍是真实失败）。
- 绝对路径必须落在允许根内；`../` 穿越与外部绝对路径判缺失（修复了旧实现的目录外放行）。
- 成功解析不改变验证状态；确实不存在仍 `failed`。

### 2.3 ZCode 订阅健康与模型解析（缺陷 #3/#4）

**根因**：`ModelCatalogService.refresh()` 只做发现/替换，不探测可用性；`resolve_model_target`
对含 `/` 的 id 直接 `partition("/")` 返回，导致不存在的 `z-ai` provider 被置顶。

**实现**：

- 新增 `control/model_health.py`：
  - `classify_model_error()` 仅从真实错误文本分类：`subscription_invalid /
    auth_invalid / quota_exhausted`；
  - 健康证据存 `agents.extra.model_health[model] = {status, reason, error, checked_at, source}`，
    不新增表、不破坏历史数据。
- `control/runner.py`：
  - `_update_model_health()`：完成 → 清除降级；失败且命中订阅/鉴权/额度信号 → 降级（审计留痕）；
  - `_pinned_agent()`：固定模型降级 → 任务 `blocked`，说明"已降级 + 重新同步或改绑"，绝不静默换模型；
  - `_model_for_agent/_verifier_model`：跳过降级模型；
  - `roles.candidates()`：跳过降级模型。
- `control/model_catalog.py`：
  - 目录行携带 `health`；
  - `sync_all(source="sync")` 对 ZCode 逐模型执行最小 headless 探测（`probe_on_sync=false`
    可关闭；默认 60s/模型），ok/degraded 写回；未知不改写既有证据。
- `adapters/zcode.py`：
  - `resolve_model_target()`：全量匹配优先 → 前缀是真实 provider 才直通 → 否则用模型段在
    真实 provider 中搜索（修复 `z-ai/glm-5.2`），全部不匹配才失败；
  - `probe_model()`：临时目录 + 最小 prompt + **0 次模型重试**；返回 ok / degraded(reason) /
    unknown；不改用户 provider 配置、不写项目文件。
- WebUI：模型下拉与 Agent 卡片标注"⚠已降级"；推荐器跳过降级（并在空结果时说明）。

**真实环境说明**：本机 ZCode 订阅当前无效，`probe_model` 的真实 CLI 探测会在
`verify_zcode_real.py` 的已有真实用例中复跑时直接得到 `subscription_invalid`（快速失败，不烧 token）；
本轮单测覆盖 ok/degraded/unknown 三条分支与目录降级闭环。

### 2.4 Trae 回执与成果采纳（缺陷 #5）

**根因**：`TraeReader.has_marker` 恒返回 `NO_TRANSCRIPT_RECEIPT`（担心输入框回声冒充回执）；
runner `reconcile_submission` 只在 accepted 时消费成果包 → Trae 完成的 T008/R2_REVIEW 无法回收。

**实现**：

- `gui/trae_reader.py::has_marker` 两条不可伪造证据（优先顺序）：
  1. **attempt 专属 result.json 完整可解析**：该路径只出现在已送达的 prompt 中，
     写到该路径即证明请求送达（只证明送达，不证明完成；完成仍由验证器判定）；
  2. **会话 DOM marker**：TreeWalker 遍历文本节点，marker 出现在输入框（contenteditable/
     textarea/textbox）之外 → 已渲染的会话消息；仅输入框命中 → `MARKER_ONLY_IN_COMPOSER`。
- `control/trae_interface.py::trae_marker_in_transcript()`：多页面探测（优先绑定页面）。
- `adapters/gui.py::reconcile_submission()`：调用 checker 前把 attempt 的 `result_path`
  注入 reader.completion_path，使 reconcile 可凭真实证据转 accepted 并采纳成果。
- 加密会话库仍然不读、不破解。

### 2.5 重任务规避 free 档（缺陷 #6）

**根因**：链路显式绑定 `opencode/glm-5.3-flash-free` 跑 Blender/GLB 重建；系统没有任何
任务重量分级，角色阶梯第一档就是 free。

**实现**：

- `control/roles.py`：`HEAVY_TASK_MARKERS`（blender/glb/gltf/三维/3d/重建/渲染/实机/帧率/
  fps/draw call/三角面/场景搭建/大规模扫描/全量扫描）；`is_heavy_task()`、`spec_is_heavy()`；
  `RolePolicy.candidates(heavy=True)` 跳过 free 档模型（不删规则，混合档位仍保留非 free）。
- 调用方：`hub.preview_split`、`hub.solve`、`runner._escalate_task` 按任务文本传入 heavy。
- `hub.recommend_models(objective/ heavy)`：重任务排除 free；返回值带 `heavy` 标记。
- `control/prompts.py`：规划规则新增"重任务不得绑定 free 档"。
- `hub.configure_chain`：重任务 + free 档 → `warnings`（保存仍允许，UI 显示并 toast 警告），
  绝不在运行中静默换模型。

### 2.6 回退规划器约束一致性（缺陷 #7）

**根因**：R3 回退计划把未解决项原文"git rm --cached 并提交"当任务指令；与计划约束
「禁止 git 提交」冲突，`--cached` 又必然产生空补丁。

**实现**：

- `control/rounds.py::DELIVERY_RULES`：成果只以工作区文件变更交付；禁止 git commit/push；
  `git rm --cached` 无补丁差异禁止使用；版本库跟踪问题写 unresolved 交人类；冲突以约束为准。
- `fallback_specs()`：实现任务 objective 增加"任务约束（逐条复述 plan.constraints）"与
  "交付机制（逐条 DELIVERY_RULES）"；未解决项原文保留（证据不被改写）。
- `runner._continuation_context()`：轮次上下文新增 `plan_constraints` 与 `delivery_rules`。
- `prompts.write_plan_request()`：轮次规划块渲染约束/交付机制并声明"冲突时按约束执行"；
  通用规划规则新增"不得要求 git commit/push 或 git rm --cached"。

### 2.7 汇总上下文最新轮次（缺陷 #8）

**根因**：`summary_context` 按任务创建顺序输出；`_cap` 超限时从列表尾部 `pop()`，
优先丢掉最新轮次；单任务字段无上限（files/tests/warnings 可极长）。

**实现**（`control/context.py`）：

- 任务按轮次倒序（`R{n}_` 解析）+ task_id 排序，输出 `round / latest_round / rounds_present /
  ordering`；changes 同样按轮次倒序并限制 60 条。
- 单任务摘要 1500 字符、files 30、tests 10、warnings 10、unresolved 12，先在条目内收缩。
- `_cap`：列表收缩策略改为"先缩最旧条目的嵌套字段，再丢最旧条目，**永不丢首项**"；
  仍超限才走整体截断兜底。
- 结果：最新轮次的 R2_T001/R2_REVIEW 在最紧预算下仍完整保留，主节点不再基于第 1 轮上下文
  reject（对应报告第 8 条与"合并审批停摆"根因）。

### 2.8 WebUI 收尾通道与交互（缺陷 #9/#10/#11）

**后端**：

- `GET /api/tasks/<uid>/attempts`：尝试列表（状态/结果文件存在/request_id/active），供 UI 采纳。
- `POST /api/runs/<id>/summary`：兼容 `{summary: {...}}`、`{path}`、`{summary_path}`；
  路径必须位于项目目录内，读到文件后走原 `submit_summary`（缺字段仍按原校验报错）。
- `POST /api/tasks/<uid>/binding` 新增 `stop_active`：
  - 运行中节点默认仍拒绝修改；
  - `stop_active=true` → 停止当前尝试（杀 CLI 进程/登记停止尝试）、任务转 blocked 并提示重试，
    记录 `task.stop_and_rebind` 审计；
  - runner 执行返回后新增**晚到结果丢弃**：尝试被停止或 `active_attempt_id` 已变化 →
    只把旧尝试标 canceled + 审计 `task.stale_attempt_discarded`，绝不覆盖新绑定/新尝试。
- 人工成果提交继续要求 `attempt_id/request_id`；UI 现在会带上选中尝试。

**前端**：

- 任务详情新增"尝试记录"表（含“采纳”按钮）与提交成果的"关联尝试"下拉。
- 链路节点新增"采纳成果"；运行/验证中的节点也可"编辑绑定"（勾选停止当前尝试）。
- 运行卡片与阻塞弹窗新增"回填汇总 JSON"（粘贴或项目内路径）。
- 阻塞卡片按任务/运行状态过滤：SUMMARY/ROUNDx_PLAN 完成、运行终态后不再残留。
- `openImportPlanModal`、`openSummaryModal`、`openAdoptModal`、`openTextInputModal`
  全部页内模态框；移除所有 `prompt()`（计划导入与 MCP 参数）。
- `pre.plain` 亮色样式用于"等待主节点 UI 执行"等长文本卡，深色底+浅色字的日志 pre 保留。
