### S04 attempt / 回执 / 会话绑定（F01/F03/F06/F07/F19）

- 新增 `attempts` 表与 `tasks.active_attempt_id`；每次执行生成 `attempt_id + request_id`，记录 workdir、result/patch/report 路径、binding 与输入 manifest。
- 每个 attempt 使用独立结果路径（`.agentloop-task/<task>/<attempt>/result.json`），重试不会读到旧成果。
- 每个 attempt 独立 patch 路径与验证报告目录；`_ensure_change` 不再复用上一 attempt 的 patch；ChangeRecord/Result/Attempt 均带 attempt 关联。
- 重试创建新 attempt，旧产物保留为证据。
- 模型证据拆为 `requested_model / selected_model_id / visible_model_label / observed_response_model / observed_known`；缺失记为 unknown，不再补成期望值。
- 人工等待拥有独立期限（`manual_wait_seconds`），超时返回 `waiting_user` 而非创建新 attempt；不再清除人工标记。
- WorkBuddy 发送要求 `currentId` 精确匹配，空值阻断。

测试：`tests/test_s04_attempts.py`。

### S05 取消 / 人工等待 / 恢复（F06/F18/F20）

- run 新增 `epoch`；取消时 epoch+1、状态 `canceled`。
- summary/verify 请求携带 cancel_event 与 epoch；返回后重新校验 run 状态/epoch，迟到结果写入 `late-summary-*` / 诊断区，不能进入验收/合并。
- `finalize_summary` 对 canceled/旧 epoch/已终态 run 不再推进。
- `resume` 会把遗留 `verifying` 任务按已有成果继续验证，不重新发送实现请求。
- 人工提交结果完成后自动唤醒控制器；高风险审批放行后自动唤醒；恢复服务输出 `runs_to_start` 并由 Hub 启动。
- Recovery 检查包含 `verifying` 任务；auto_resume 时 run 回到 `ready` 而非永久 paused。

测试：`tests/test_s05_reconcile.py`、`tests/test_recovery_handoff.py`、`tests/test_closed_loop.py`。

### S06 输入 manifest 与工作树复用（F02/F19/F21）

- 输入快照 = base commit + 有序依赖 artifact 的 SHA-256 + task_uid；manifest 写入 attempt 与 worktree 旁车文件。
- 复用工作树必须 manifest、task_uid、attempt 序号全部一致；否则保留旧目录并在旁创建新的 Hub 自有快照，绝不删除用户/未知工作树。
- 上游补丁缺失或无法应用 → `ConflictError` 立即失败；反向 patch check 仅作诊断。
- 同 Agent 会话可续接，但工作树按节点独立；节点不再继承未声明依赖的代码。

测试：`tests/test_s06_manifests.py`、`tests/test_session_reuse.py`。

### 2.3 真实链路 T003 在 verifying 失败（2026-11-06 续）
