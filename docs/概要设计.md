# AgentMesh OS 概要设计

文档版本：V2.1（统一 Web 控制端 + 模型目录 + 版本台账 + REA MCP）  
日期：2026-11-03  
需求基线：`01-需求整理-v1.docx`  
代码位置：`agentloop_hub/`（包名保留历史兼容；产品与 CLI 为 AgentMesh OS / `agentmesh`）

---

## 1. 设计结论

AgentMesh OS 不是一个“更强的 Agent”，而是一个**用户主权型本地多 Agent 协同操作系统**：

- 主节点不是主 Agent，而是用户指定的**决策与汇总节点**；
- Controller 是确定性软件，负责记忆、调度、路由、成本与治理，不把控制决策交给大模型；
- 其它 Agent 全部降级为资源池，由 Capability Router 自动选择；
- 所有 Prompt、Response、文件变更、任务状态、知识与工作流事件经过 Context Bus；
- 控制平面默认不复制完整聊天或上下文，只同步**结构化状态与成果摘要**；
- 关键节点（架构、验收、合并、发布）必须由人类批准；
- 单一 Web 入口完成“项目初始化 → Prompt → 主/子 Agent 与模型选配 → 审批/运行 → 实时监控”；
- 模型清单只来自真实探测与用户登记；Agent 版本进入台账，升级后能力退化会触发漂移提示。

```text
用户
 │
 ▼
统一 Web 指挥中心（单入口 + SSE 实时监控）
 │
 ▼
AgentMesh Controller
 ├── Agent Model Catalog
 ├── Unified Memory
 ├── Task Scheduler
 ├── Capability Router
 ├── Cost Optimizer
 ├── Agent Version Ledger
 └── Human Governance
 │
 ▼
Context Bus（append-only events + subscriptions + cursor）
 │
 ▼
Trae / Qoder / WorkBuddy / ZCode / DSH / OpenCode / Claude Code /
Gemini CLI / Codex CLI / Cursor / Aider / REA Studio (MCP) / 任意 CLI 或接力 Agent
```

实现语言与依赖：Python 3.10+（本机 3.12.7）；标准库 `sqlite3`、`http.server`、`argparse`、`subprocess`、`threading`；第三方 PyYAML、cryptography、zstandard、pytest。

## 2. 七个模块

### 2.1 Agent Connector

- 统一抽象：`{"agent_id": ..., "capability": [...]}`，见 `connectors.agent_descriptor` 与 `connector_manifest`。
- 能力词表：读/写/终端/联网/MCP/会话读写/结构化输出/流式/后台/代码生成/审查/架构/测试/文档/分析/执行/本地 MCP。
- 产品画像 `CONNECTOR_PROFILES` 覆盖需求列出的 12 类产品，并额外覆盖 Qoder CN。
- 发现策略：只有真实可执行文件或存储/配置目录存在才标记可用；不虚构在线状态、不 GUI 自动化、不读私有隐藏状态。
- 接入等级：L0 人工 / L1 文件协同 / L2 结构化任务 / L3 会话或 CLI / L4 原生双向（不承诺）。
- 任意 CLI 或文件接力 Agent 可手动注册；统一执行契约是“读任务包，写结果 JSON”。
- REA Studio 通过项目级 `.mcp.json` 自动发现，使用真实 MCP stdio 适配器：`initialize` → `notifications/initialized` → `tools/list` / `tools/call`；不猜测工具参数，只暴露服务端返回的 inputSchema。
- 模型目录 `agent_models` 记录每个 Agent 的模型与来源（`discovered / session / cli / registered / user`）；主 Agent 模型写入 `main_nodes`，子 Agent 模型写入 `agents.extra.selected_model`。

### 2.2 Unified Memory

八类规范记忆：

| 类型 | 同步级别 | 来源 |
| --- | --- | --- |
| `message` | L1 | 历史会话归档摘要 |
| `task_state` | L2 | 任务状态快照 |
| `project_index` | L3 | 项目事实、目录/文件/命令索引 |
| `code_structure` | L3 | 源码目录、测试目录、入口点 |
| `knowledge` | L4 | 问题解决、经验、外部知识 |
| `decision` | L4 | 计划批准、主节点切换、汇总 |
| `workflow` | L5 | 运行阶段、进度、待审批 |
| `user_preference` | L3 | 用户偏好 |

属性：来源、置信度、scope、有效期、失效条件、最后验证时间、可注入性、冲突组。

冲突：同类型同标题不同内容且都 active → 全部标记 `conflict` 并生成 `conflict_group`；用户选择保留项，其余 `superseded`。

启动引导包：`MemoryService.bootstrap` 输出项目、分组记忆、最近总线事件与五级计数；任务包与规划请求都会注入，保证任何 Agent 启动时拿到同一份项目状态。

### 2.3 Context Bus

- 存储：`bus_events`，字段 `seq/event_id/project_id/topic/kind/source/correlation_id/sync_level/payload/tokens/prev_hash/hash/created_at`。
- 只追加：数据库触发器拒绝 `UPDATE`/`DELETE`；每个项目独立哈希链，`bus verify` 可校验。
- 事件类型：`prompt / response / file_change / task_state / workflow / knowledge / decision / governance / routing / verification / cost / message / agent_status / project_index`。
- 写入路径：
  - Store 是任务/运行/记忆/审批/变更/结果/会话的单一写路径，写后自动 emit；
  - Planning/Runner 显式发布 prompt 与 response 摘要；
  - Cost Optimizer 发布节省事件；
  - Router 发布路由决策。
- 订阅：`bus_subscriptions` 保存 subscriber、主题/类型过滤、游标；`poll` 原子推进游标，支持多 Agent 独立消费。
- 回放：按 seq/topic/kind 重放。
- 成本纪律：单事件超过 `bus_payload_max_tokens` 时保留结构化摘要并标记 `_truncated`；不把完整日志塞进总线。

### 2.4 Task Scheduler

- 任务拆分由主节点规划（`planning.py`）产出 DAG；
- `TaskSpec.priority` 0..10，默认 5；
- 就绪条件：所有依赖已完成；同一层按优先级降序、创建时间与 task_id 稳定排序；
- 前置失败/取消/拒绝 → `blocked`；
- `retry_limit` 控制重试；最终失败数达到阈值触发运行级熔断；
- 并发由 `max_parallel` 控制。

### 2.5 Capability Router

评分是确定性的、可解释的：

```text
required = task_type 映射能力 ∪ task.required_capabilities
eligible = 在线 && 不是仅会话读取 && 具备全部 required
score = w_capability*1.0
      + w_success*success_rate
      + w_verification*verification_pass_rate
      + w_speed*speed_score
      + w_cost*cost_score
      + 0.02*access_level + suggested_bonus(0.03)
```

- 默认权重：能力 0.40、成功率 0.25、验证 0.15、速度 0.10、成本 0.10。
- 成功率使用拉普拉斯平滑；无历史时中性先验 0.5。
- 速度/成本按配置参考值归一化。
- 主节点默认不参与子任务执行，除非该任务是重试且已分配给主节点。
- 每次选择写入 `routing_decisions`（评分、明细、候选、原因），并发布 `routing` 总线事件。
- `route rank/task/scores/decisions`、`/api/router/*` 可审计每次选择。

### 2.6 Cost Optimizer

| 策略 | 实现 |
| --- | --- |
| Context Compression | `compress_context` 按 Token 上限裁剪并记录节省 |
| Semantic Cache | 只读任务 + 同一文件树哈希 + 意图 Jaccard ≥ 0.82 时复用成果 |
| Intermediate Result Reuse | 依赖任务只接收上游成果 digest；相似历史分析结果作为提示注入 |
| Agent Benchmark | 成功率、验证通过率、平均 Token/成本/耗时、综合分；给出每个任务类型的“ cheapest sufficient” |
| 节省账本 | `savings_ledger` 记录 exact/semantic cache、context compression、intermediate reuse 的 Token 与成本节省 |

安全约束：可写任务永不自动复用成果；语义缓存只在文件基线一致时命中；缓存命中后仍走控制平面验证。

### 2.7 Human Governance

| 门禁 | 触发 | 结果 |
| --- | --- | --- |
| 架构设计 | 计划含 `architecture` 类型任务 | 未批准则计划不能批准/分发 |
| 计划批准 | 计划生成或导入 | 批准后才创建运行与任务 |
| 验收确认 | 全部任务完成并生成汇总 | 批准后创建合并审批；拒绝则运行失败 |
| 代码合并 | 验收通过 | 批准后应用 Patch |
| 发布上线 | 合并完成且验收通过 | 单独批准；只记录门禁，不自动部署 |

审批详情包含 what/why/agent/model/files/风险/预计 Token/回滚/推荐选项；审计与总线都会记录。

### 2.8 统一 Web 控制端与扩展能力

| 能力 | 实现 | 说明 |
| --- | --- | --- |
| 项目初始化/切换 | `workspace/init.py`、`workspace/manager.py` | 创建目录、`git init`、新空目录生成初始 commit；支持运行中切换项目 |
| 原始 Prompt | `POST /api/plans`、`/api/ask` | 主 Agent 规划，Web 轮询 Job 状态 |
| 主/子 Agent 模型选配 | `control/model_catalog.py` | 真实探测 + 用户登记；主模型写 `main_nodes`，子模型写 `agents.extra.selected_model` |
| 实时全量监控 | `GET /api/stream`（SSE） | Context Bus 事件、任务 stdout 增量、运行/任务/成本/审批/漂移快照 |
| REA MCP | `adapters/mcp.py` | 真实 MCP stdio；列出 229 个工具，按服务端 schema 调用 |
| 版本台账 | `control/versioning.py` | 版本 + 适配器 + 能力指纹；升级后能力退化标记 `drift` |

模型来源优先级：`user > registered > cli > session > discovered`。刷新发现模型时只替换机器探测来源，保留用户登记与手填模型。

## 4. 协议

### 4.1 任务包

- `task.json`：目标、scope/out_of_scope、依赖、验收、验证命令、预算、优先级、Agent、记忆、bootstrap、上游成果摘要。
- `prompt.md`：人/Agent 可读的最小任务说明与强制输出格式。
- `result-schema.json` / `result-template.json` / `context.json`。
- 工作目录内 `.agentloop-task/<task_id>/` 运行时副本，不进入 Patch。

### 4.2 成果包

17 个必填字段：`task_id, agent_id, status, summary, findings, files_read, files_changed, commands_run, tool_calls, tests, evidence, risks, unresolved_items, artifacts, token_usage, cost_estimate, recommended_next_action`。

`ResultPackage.digest()` 只保留主节点/依赖任务需要的结果摘要，用于 result sync。

### 4.3 验证报告

`task_id, verifier_agent, verification_status, checks, warnings`；执行 Agent 不能是唯一验收者。

## 5. 执行流程

```text
Web 指挥中心：初始化/打开项目 → 输入 Prompt → 选配主/子 Agent 模型
 → 主节点生成计划（或用户导入）
 → 计划校验（唯一 ID、无环、scope、priority）
 → [架构审批，仅 architecture 任务]
 → 计划审批
 → 创建 run/tasks，base_commit
 → 任务调度（优先级 + 依赖）
 → Capability Router 选 Agent
 → 预算 / 高风险 / 租约检查
 → 独立 Worktree + 任务包
 → [精确缓存 → 语义缓存] 命中则复用并验证
 → Agent 执行（CLI/OpenCode/文件接力）
 → 结构化成果包
 → Patch + Change
 → 控制平面验证 + 可选独立 Agent 验证
 → 任务 completed / failed / 重试 / blocked
 → 全部完成：主节点汇总（只读压缩上下文）
 → 验收确认审批
 → 合并审批 → Patch 合并 → 合并后验证
 → 发布审批（人类门禁）
 → SSE 实时监控与版本漂移提示
```

## 6. 隔离、合并与回滚

- 每个任务（包括只读分析）在 `.agentloop/runs/<run>/worktrees/<task>` 的 detached Worktree 中执行。
- 可写任务派发时获取 scope 租约；scope 重叠不能并行。
- Patch：`git add -N` + `git diff --binary HEAD`，排除 `.agentloop-task/`。
- 合并前检查：验收已通过、合并审批已批准、基线分支一致、用户工作区无重叠修改、跨任务文件集合无交集、Patch 可应用。
- 合并后运行任务验证命令；失败保留现场，可回滚任务/文件/整个运行。

## 7. 恢复与审计

检查点覆盖计划、架构/验收/合并、运行开始、任务分发、缓存命中、变更、验证、完成/失败、熔断、恢复。

恢复策略：中断任务有合法成果 → 转 verifying；否则 paused 并保留 Worktree；释放租约；`auto_resume` 不自动重跑已修改文件的任务。

审计事件覆盖项目、Agent、主节点、计划、审批、运行、任务、变更、合并/回滚、记忆、会话、上下文读取、路由、成本节省、恢复。哈希链 + 触发器保证只追加。

Context Bus 另有独立哈希链；`doctor` 同时校验审计链与总线链。

---

## 8. 安全边界

- 本地优先：状态默认在项目内 `.agentloop`。
- 最小权限：任务包声明 scope/out_of_scope/禁止事项；子任务在隔离 Worktree。
- 路径白名单：合并只对项目内路径；越界 scope 触发高风险审批。
- 命令分级：危险命令模式命中即高风险审批；验证命令由控制平面复跑并记录退出码。
- 密钥：提示词显式禁止读取/输出凭据；高风险文件模式覆盖 `.env`/私钥。
- 外部传输：不自动上传项目；会话读取只读本地文件。
- 残余风险：Agent 进程以用户权限运行，不是强沙箱；依靠 Worktree、范围验证、合并门禁、审批与审计降低风险。
- 语义缓存/结果复用不会绕过验证；写任务不复用成果。
- 发布审批只记录人类决定，不自动部署。

## 11. 明确取舍

1. **主节点是决策节点，不是唯一执行者**：架构/分析任务可由路由器选择子节点；最终架构批准仍由人类。
2. **GUI Agent 的 L2 语义**：文件接力接收结构化任务并返回结构化成果，但需要用户在 GUI 中触发；不宣称自动执行。
3. **不自动选择“全球最强模型”**：主模型由用户指定；路由器只按本地实测能力/成本/速度/成功率选执行节点。
4. **不复制全部聊天**：只同步会话摘要与结构化成果；完整归档保留在 `.agentloop/conversations`。
5. **发布门禁不部署**：项目只记录人类批准，部署由用户既有流程执行。
6. **模型不自动“越权”选择**：控制台只提供本机真实模型清单与用户登记入口；不会因为某个模型“更强”而绕过用户选配。
7. **版本漂移不自动修复**：只记录与提示；是否回滚 Agent、修改适配器或重新注册由用户决定。
8. **REA 只走 MCP**：不逆向 REA 内部实现，不直接调用其私有数据库；工具参数必须符合服务端 inputSchema。
9. **P2 未实现**：多电脑同步、团队权限、云端调度、GUI 自动化、会话写回、插件市场。
