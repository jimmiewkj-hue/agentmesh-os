## 1. 实现结论

需求整理-v1 的七个模块已全部落地，没有只搭框架或占位实现：

```text
Agent Connector → Unified Memory → Context Bus → Task Scheduler
→ Capability Router → Cost Optimizer → Human Governance
```

主链路可运行：

```text
Web 指挥中心初始化/打开项目 → 输入 Prompt → 选配主/子 Agent 模型
→ 发现 14 类本机 Agent（含 REA MCP） → 指定主节点/主模型
→ ask/规划生成结构化计划 → [架构审批] → 计划批准
→ 优先级 + 依赖调度 → 能力路由自动选 Agent
→ 独立 Worktree 执行 → 结构化成果包 → 确定性/独立验证
→ 结果摘要同步 + 精确/语义缓存命中
→ 主节点汇总 → 验收确认 → 合并审批 → Patch 合并
→ 发布审批（人类门禁） → 审计/总线/成本/记忆持久化
→ SSE 实时监控 + Agent 版本漂移提示
```

实现规模：

- `agentloop_hub/`：64 个 Python/HTML/JS 文件，约 17,344 行。
- `tests/`：28 个文件（含 fixtures），约 3,253 行，**128 个测试**。

### 2.4 成本与治理

- 精确缓存、语义缓存、上下文压缩、上游成果复用均写入 `savings_ledger`。
- `benchmark` 输出成功率、验证通过率、平均 Token/成本/耗时与综合分，并给出每类任务的 cheapest sufficient。
- 架构任务先过架构审批；运行完成后必须验收确认；合并后发布需单独审批。

### 2.5 统一 Web 控制端、模型与版本

- **项目初始化**：`initialize_project` 创建目录、`git init`；空目录生成初始 commit，保证 Worktree 可立即创建；`WorkspaceManager` 支持运行中切换项目。
- **模型目录**：真机 14 个 Agent、93 个模型。来源为 CLI 输出 / 会话事件 / provider 配置 / 用户登记；`agent_models` 去重并保留来源优先级。主模型写 `main_nodes`，子模型写 `agents.extra.selected_model`，执行器优先使用选配结果。
- **版本台账**：`agent_versions` 记录版本、适配器、能力指纹、变更明细与兼容状态；版本升级且能力减少 → `drift`，控制台与 `doctor` 均可见。
- **SSE 监控**：`/api/stream` 推送 `hello / bus / snapshot / logs / ping`；快照含运行、任务计数、成本、审批、Agent 状态、漂移数；日志按任务 stdout 增量读取。
- **REA MCP**：自动读取 `D:\qoder\rea\.mcp.json`，真实握手后返回 229 个工具（`rea` v6.8.0，协议 `2024-11-05`）；工具参数必须符合服务端 inputSchema。

## 6. 已知限制

1. **GUI Agent 需人工触发**：Trae/Qoder/ZCode/WorkBuddy/DSH/Cursor 为 L2 文件接力，不是自动 GUI 控制。
2. **外部 CLI 依赖登录/额度**：OpenCode/Claude Code/Gemini CLI/Codex CLI/Aider 需要用户自行完成认证；未安装时显示离线。
3. **不是强沙箱**：Agent 进程以当前用户权限运行；隔离依靠 Worktree、scope 校验、合并门禁、审批与审计。
4. **运行要求 Git**：Worktree/Patch 隔离依赖 Git；非 Git 目录可通过 Web 控制台初始化。
5. **Trae 模型不可自动探测**：其状态在加密数据库；系统不猜测，需用户手动登记。
6. **版本漂移不自动修复**：只记录与提示。
7. **发布门禁不部署**：只记录人类批准，不自动推送/上线。
8. **语义缓存是本地确定性相似度**：不是向量嵌入；只对只读任务、同一文件基线生效，阈值 0.82。
9. **REA 仅通过 MCP 接入**：不逆向其内部实现，不直接调用私有数据库。
10. **P2 未实现**：多电脑同步、团队权限、云端调度、GUI 自动化、会话写回、插件市场。
